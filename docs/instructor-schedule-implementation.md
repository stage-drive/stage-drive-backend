# Робочий графік і недоступність інструктора (PR 1 з 3)

## Мета

Перейти від слотів, які ADMIN створює вручну (`practice_slots`, PR #80/#81), до **обчислених** слотів:
вільний час = тижневий графік інструктора − недоступність − заброньовані заняття. Цей PR додає дані й керування ними.
Обчислення слотів і бронювання — PR 2, видалення `practice_slots` — PR 3.

## Рішення

1. **Слоти не зберігаються.** PR 2 рахує їх на льоту. Бронювання створює `DrivingLesson` напряму, без `slot_id`.
2. **Авто в графіку немає.** Авто бронювання — `Student.carId`, перевіряється `requirePracticeCar`. Графік не застаріває,
   коли авто переприв'язують, ремонтують чи видаляють.
3. **Недоступність над заброньованими заняттями — `409`** зі списком занять у форматі `scheduleConflict`. Адмін спершу
   скасовує чи переносить їх; нічого не скасовується мовчки.
4. **Час графіка — хвилини від півночі** (`SmallInt`, 540 = 09:00) з `CHECK 0 <= start < end <= 1440`. API приймає й
   повертає `HH:MM`; `24:00` — до півночі. Інтервал через північ не підтримується.
5. **Перерва — проміжок між інтервалами.** Кілька рядків на день (`09:00–13:00` + `14:00–18:00`), окремих колонок
   перерви немає. Неперетин рядків одного дня перевіряє сервіс: `PUT` замінює тиждень цілком.
6. **Недоступність — моменти `[startsAt, endsAt)`**, як у занять. Цілі дні API приймає як `startDate`/`endDate`
   (включно) і перетворює в місцеві північ → північ за `Organization.timezone`. Можна задати й кілька годин.
7. **Ізоляція автошкіл на рівні БД** — складені FK `(instructor_id, organization_id) → users(id, organization_id)`, як у
   `practice_slots`. Видалення інструктора — `CASCADE`: графік і недоступність — налаштування, не історія.
8. **Advisory-ключ `instructor:<id>`.** `PUT` графіка і `POST` недоступності беруть той самий ключ, що створення й
   зміна практичних занять, тож заняття не проскочить між перевіркою і записом (див. інтеграційні тести).
9. **Заняття, які створює ADMIN/INSTRUCTOR, перевіряють недоступність, але не графік.** `findPracticeConflicts`
   повертає конфлікт `resource: 'INSTRUCTOR', lessonType: 'TIME_OFF'` (lessonId — id недоступності). Графік не
   перевіряється навмисно: так адмін може додати разову додаткову зміну без окремої таблиці.
10. **Зміна ролі інструктора з графіком блокується** (`INSTRUCTOR_HAS_WORKING_HOURS_MESSAGE`), як і з авто чи слотами.

## Ендпоінти

| Метод | Шлях | Ролі | Що робить |
|---|---|---|---|
| `GET` | `/api/instructors/:instructorId/working-hours` | ADMIN, INSTRUCTOR (свій) | тиждень у поясі автошколи |
| `PUT` | `/api/instructors/:instructorId/working-hours` | ADMIN | замінює тиждень цілком; `{ intervals: [] }` очищає |
| `GET` | `/api/instructors/:instructorId/time-off?from&to` | ADMIN, INSTRUCTOR (свій) | недоступності, що перетинають вікно (`resolveRange`) |
| `POST` | `/api/instructors/:instructorId/time-off` | ADMIN | `{ type?, reason?, startDate, endDate? }` або `{ …, startsAt, endsAt }` |
| `DELETE` | `/api/instructors/:instructorId/time-off/:timeOffId` | ADMIN | фізичне видалення |

CORS отримав `PUT` у [configure-app.ts](../src/configure-app.ts): раніше дозволялися лише GET/POST/PATCH/DELETE.

## Помилки

Порядок, як у `PracticeSlotsService`: `403` і `400` — до запитів у БД, потім `404`, потім `409`.

| Випадок | Код | Поле / повідомлення |
|---|---|---|
| Роль не підходить, INSTRUCTOR відкриває чужий графік | 403 | `Insufficient permissions` |
| Час не `HH:MM`, невідомий день, зайве поле | 400 | `intervals.<i>.<поле>` |
| `end <= start`, інтервал коротший за 15 хв | 400 | `intervals.<i>.end` |
| Інтервали одного дня перетинаються | 400 | `intervals.<i>` (пізніший елемент) |
| Обидві форми недоступності чи жодної | 400 | `body` |
| `endDate < startDate`, `endsAt <= startsAt`, довше 366 днів | 400 | `endDate` / `endsAt` |
| Недоступність уже закінчилася | 400 | `endDate` / `endsAt` |
| Інструктора нема в автошколі, недоступність не знайдено | 404 | `Instructor not found` / `Time off not found` |
| Інструктор не ACTIVE (для `PUT` і `POST`) | 409 | `INSTRUCTOR_NOT_ACTIVE_MESSAGE` |
| Недоступність над SCHEDULED-практикою інструктора | 409 | `conflicts: [{ resource: 'INSTRUCTOR', lessonType: 'PRACTICE', … }]` |
| Заняття під час недоступності | 409 | `conflicts: [{ resource: 'INSTRUCTOR', lessonType: 'TIME_OFF', … }]` |

## Часові пояси

[zoned-time.ts](../src/common/time/zoned-time.ts) — перетворення місцевого часу в момент лише через `Intl`, без
залежностей. Сюди ж перенесено `localDate` з `lessons.service.ts`.

- `zonedTimeToUtc(date, minute, tz)` — `null`, якщо місцевого часу немає (перехід на літній час): PR 2 пропустить
  такий слот. Для Києва це 03:00–04:00 в останню неділю березня, поза робочими годинами.
- `startOfLocalDay(date, tz)` — межі цілих днів недоступності; пропущену північ (деякі пояси) зсуває вперед.
- Тести покривають обидва переходи для Києва, Нью-Йорк і Сантьяго.

## Наступні PR

1. **Обчислені слоти й бронювання.** `computeAvailableSlots` (чиста функція): для кожної місцевої дати вікна — інтервали
   її дня тижня, крок `PRACTICE_DEFAULT_DURATION_MIN`, мінус недоступність і `findStudentSlotBlockers`. Маршрут
   `GET /practice-slots/available` лишається, елементи втрачають `id`. `POST /practice-slots/book { scheduledAt }` — під
   ключами `instructor:`, `car:`, `student:`, перевіряє, що час — один зі згенерованих, і `findPracticeConflicts`
   (недоступність уже там).
2. **Видалення `practice_slots`.** Міграція `DROP TABLE`, CRUD слотів, `findSlotConflicts`, `lockPracticeSlot`,
   `practice-slot-view.ts`, `lessonType: 'SLOT'`, `INSTRUCTOR_HAS_SLOTS_MESSAGE` і їхні тести. Перелік підтверджується
   перед видаленням.

## Поза скоупом

- Графік з датою набуття чинності (`effectiveFrom`).
- Святкові дні всієї автошколи.
- Попередження, коли новий графік лишає заброньовані заняття поза робочим часом.
- Буфер між заняттями й мінімальний час до бронювання.
- Заявки на недоступність від самого інструктора.
- `EXCLUDE`-обмеження на перетин інтервалів у БД (потребує `btree_gist`).
